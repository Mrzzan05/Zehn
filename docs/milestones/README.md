# Milestones Directory

## Purpose

This directory contains milestone documentation.

Each milestone represents a meaningful development stage with:

- goals
- scope
- implementation progress
- acceptance criteria
- final results

---

# Milestone Philosophy

A milestone is not just a collection of features.

A milestone represents a stable improvement in the system foundation.

---

# Milestone Contents

Each milestone document should describe:

## Objective

What problem this milestone solves.

---

## Scope

What is included.

---

## Non Scope

What is intentionally excluded.

---

## Technical Changes

Important implementation changes.

---

## Tests

Required validation.

---

## Completion Criteria

How success is measured.

---

# Naming Convention

Format:

```
M<number>.md
```

or

```
R<number>.md
```

Examples:

```
M1.md

M2.md

R1.md

R2.md
```

---

# Milestone Lifecycle

```
Planned

↓

Active

↓

Completed

↓

Archived
```

---

# Rules

A milestone should not contain:

- temporary debugging notes
- personal task lists
- unrelated ideas

Those belong in:

- knowledge/
- NEXT_TASK.md
- RFC documents
